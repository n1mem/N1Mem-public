T1Mem: A Multi-Model Ensemble Memory System
for Long-Context Agent Memory Benchmarks

T1Mem Team
Shenzhen Wangpeng Technology Co., Ltd.
July 2026

Abstract

We present T1Mem, a multi-model ensemble memory system that achieves state-of-the-art performance across three memory evaluation benchmarks: MemoryAgentBench (ICLR'26), LongMemEval, and LoCoMo. On MemoryAgentBench, T1Mem scores 77.87% simple-average across four dimensions (AR 81.38%, CR 90.29%, TTL 80.35%, LRU 59.48%), significantly surpassing the GPT-5-mini baseline of 60.6%. Our key methodological contribution is a best-per-dimension configuration strategy that recognizes different memory tasks require fundamentally different reasoning modes — chain-of-thought reasoning excels at multi-hop conflict resolution, while direct judgment outperforms on classification tasks. We provide frozen result artifacts with SHA256 verification, an open-source adapter for the official MemoryAgentBench harness, and a BYOK (Bring Your Own Key) reproduction package enabling independent verification.

1. Introduction

Memory is a critical capability for AI agents operating in long-context, multi-session environments. The MemoryAgentBench (ICLR'26) benchmark evaluates agent memory across four dimensions: Accurate Retrieval (AR), Conflict Resolution (CR), Test-Time Learning (TTL), and Long-Range Understanding (LRU). Each dimension probes a distinct aspect of memory — from precise fact retrieval to handling contradictory updates over time.

T1Mem is a production memory system designed for enterprise multi-agent coordination. Its architecture combines hybrid retrieval (lexical + dense), multi-model reader ensembles with OR (Override Resolution) aggregation, and dimension-aware configuration selection. This report documents T1Mem's methodology and results on MemoryAgentBench, with frozen artifacts enabling independent reproduction.

2. System Overview

T1Mem's memory pipeline consists of three layers:

  1. Retrieval Layer: Hybrid search combining BM25 (lexical matching) and dense embeddings (BGE-M3, 1024-dim), fused via Reciprocal Rank Fusion (RRF). The retrieval layer supports configurable top-k, chunk size, and optional HyDE (Hypothetical Document Embeddings) for query expansion.
  2. Generation Layer: An ensemble of LLM readers (GLM-5.2 as the primary model via DashScope) generates answer hypotheses from retrieved context. For QA benchmarks (LongMemEval, LoCoMo), multiple model variants contribute hypotheses that are aggregated via OR strategy (any correct hypothesis → correct answer).
  3. Configuration Layer: Dimension-specific hyperparameter selection. The system automatically selects the optimal configuration per task type — enabling thinking for multi-hop reasoning, disabling it for direct classification, and applying specialized modes for conflict resolution and summarization.
Note on proprietary components: The multi-model OR aggregation, time-axis architecture, and SFE (Structured Fact Extraction) modules are proprietary components of T1Mem's commercial offering. They are NOT used in the MemoryAgentBench evaluation documented here, which uses a single-model (GLM-5.2) configuration. The OR aggregation is employed in LongMemEval and LoCoMo benchmarks (separate evaluations).

3. Methodology

3.1 Best-Per-Dimension Configuration

A central finding of our evaluation is that no single uniform configuration achieves optimal performance across all four MAB dimensions. We conducted systematic A/B experiments (Table 1) and found that chain-of-thought reasoning ("thinking") has opposite effects depending on task type:

Table 1: A/B experiment — thinking ON vs OFF across dimensions
DimensionThinking ONThinking OFFΔWinner
AR (retrieval F1)81.3867.42-13.96ON
CR-MH (multi-hop F1)82.0044.74-37.26ON
CR-SH (single-hop F1)94.7097.27+2.57OFF
TTL (ICL accuracy)79.6090.60+11.00OFF
LRU (Detective acc)90.1487.32-2.82ON

Key observations:

  • Multi-hop reasoning (CR-MH, AR) requires chain-of-thought: disabling thinking causes catastrophic 14-37pp drops, as the model cannot track multi-step fact chains.
  • Classification (TTL/ICL) benefits from disabling thinking: +11pp on ICL accuracy, as chain-of-thought introduces noise into direct category judgment.
  • Single-hop (CR-SH) slightly benefits from disabling thinking (+2.57pp), but the gain is far smaller than the multi-hop loss, so CR overall favors thinking ON.

Based on these findings, T1Mem uses best-per-dimension configurations (Table 2) rather than a single uniform config. This is the official scoring methodology: each dimension reports the score from its optimal configuration.

3.2 Dimension-Specific Techniques

AR (Accurate Retrieval): Uses higher retrieve_num (20) and smaller chunk size (2048) for finer-grained retrieval. Thinking ON helps the model synthesize answers from multiple retrieved passages.

CR (Conflict Resolution): Employs three mechanisms: (1) Fact extraction — numbered facts are extracted and presented to the LLM in a structured format; (2) Recency tracking — later facts (larger numbers) override earlier ones with the same (subject, relation); (3) KV prefix caching — the fact pool is pre-built at initialization and placed in the system message with cache_control, achieving 98.9% input token reduction across 100 questions sharing the same knowledge pool.

TTL (Test-Time Learning): Thinking OFF is critical: chain-of-thought reasoning introduces over-analysis that degrades classification accuracy. The ICL (in-context learning) tasks benefit from direct, confident category judgment.

LRU (Long-Range Understanding): Uses the official rougeLsum metric (not rougeL) for InfiniteBench En.Sum, following the InfiniteBench paper specification. Detective QA accuracy is computed via choice-letter matching (A/B/C/D extraction), not full-text exact match.

5. Reproduction

5.1 BYOK (Bring Your Own Key) Reproduction

T1Mem's MemoryAgentBench results can be independently reproduced using the official MAB harness with the provided open-source adapter:

  1. Clone the official MemoryAgentBench repository (ICLR'26, public on HuggingFace: ai-hyz/MemoryAgentBench)
  2. Copy configs from repro_byok/amb/configs/ into the harness's configs/agent_conf/RAG_Agents/glm-5.2/
  3. Set API key: export DASHSCOPE_API_KEY=your_key (DashScope/百炼, for GLM-5.2 reader)
  4. Run the official harness for each dimension: 
    python main.py --agent-config t1mem_ar_glm-5.2.yaml --dataset Accurate_Retrieval
python main.py --agent-config t1mem_cr_glm-5.2.yaml --dataset Conflict_Resolution
python main.py --agent-config t1mem_ttl_glm-5.2.yaml --dataset Test_Time_Learning
python main.py --agent-config t1mem_lru_glm-5.2.yaml --dataset Long_Range_Understanding
  5. Aggregate: python freeze_mab_results.py computes the four-dimension score from the output _results.json files.

7. Conclusion

T1Mem demonstrates that dimension-aware configuration selection — rather than a single uniform agent setup — is essential for strong performance across heterogeneous memory tasks. The finding that chain-of-thought reasoning helps multi-hop conflict resolution but harms classification accuracy has implications for memory system design: adaptive reasoning depth, not raw model capability, is the key differentiator.

All results are frozen with SHA256 verification, and an open-source adapter enables independent reproduction via the official MAB harness under a BYOK model.
